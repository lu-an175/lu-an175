## 踩到的坑：房态口径

第一版 `_build_room_status` 把「当前空房」（总房 − 在住）当成「可售余量」，
结果导出数据出现 `可售空房 22` 却 `预抵 23` 的矛盾 —— 22 间接不下 23 间客。

正确口径：
```
今日可周转房 = 总房 − 在住 + 预离 − 维修 − 停用
可售余量     = 可周转房 − 预抵        ← 日报要用这个
```
漏算预离会让店长误判去化压力、做出过头的降价决策。已在 SKILL.md 里把两个概念写清楚并禁止用「空房」这种含糊说法。

另一处：`occupied` 现在指「此刻已入住」，`arrivals` 是「今天还会来的」，
两者之和才是当日售出间夜 —— 否则日报里「在住 105」会把还没到店的客人算进去。
